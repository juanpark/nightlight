# API mocks

Sample data for building the web app before the backend is live. The contract is in
[`docs/API.md`](../../docs/API.md). Generated by `python3 scripts/gen_mocks.py` from one consistent story; don't edit
the generated files by hand (`config.json` and `errors.json` are hand-written).

## Phases: one moment in time each

Each folder under `phases/` is a complete, consistent snapshot of the same demo user (what the Firestore listeners
would show). Start with **`before_approval`**. `phases.json` lists the order, the action that moves between phases,
and the matching stream sample.

| Phase | What the user sees |
|---|---|
| `before_approval` (default) | the Pi's disk is 94% full; the agent proposed cleaning up logs; the approval card is waiting. Two earlier cleanups succeeded |
| `after_approval` | approved: disk 61%, the agent's follow-up reply, and a promotion offer ("gone well 3 times, let me handle it?") |
| `auto_success` | offer accepted; the disk filled again; the cleanup ran automatically, with no card |
| `auto_failed` | same, but the automatic cleanup failed: no card, trust drops to "Ask me for new things" |
| `resetting` | Reset pressed: show a blocking "Resetting the demo…" until `demo.state` is `ready` |
| `after_reset` | fresh sample home at generation 4; old cards are hidden tombstones (deciding one answers 409 `stale`) |
| `gallery` | every card state side by side, for styling only (not one moment in time) |

Files per phase: `user.json` (`users/{uid}`), `devices.json` (devices with their services nested for convenience;
Firestore keeps services as a subcollection), `events.json`, `actions.json`, `trust.json`, `sessions.json` (each
session with its `messages`, ordered by `seq`, and its `turns`), plus `decide_response.json` in `after_approval`.

## Streams

`sse/*.txt` are byte-exact Server-Sent Events: each event is a `data:` line followed by a blank line; lines starting
with `:` are comments. Each file is one response and ends with exactly one `done` or `error` event.

## Notes for the web app

- Every document carries `demoGeneration`. Show only documents whose `demoGeneration` equals `users/{uid}.demoGeneration`.
- Times are ISO 8601 UTC strings here and in the API. Firestore listeners return Timestamp objects: convert them in one
  adapter so the UI gets the same shape from mocks and from Firestore.
- Chat: create `clientRequestId` with `crypto.randomUUID()` when sending; reuse it to retry. "Ask again" = new id.
- Streams are `POST` requests read with `fetch()` and a `ReadableStream`.
- After `approval_request`, the card is at `users/{uid}/actions/{actionId}`. After approving, open
  `POST /api/turns/{continuationTurnId}/stream` for the agent's reply.
- Automatic actions (`decision.by = "auto"`) show no card and have no continuation: they end `done` **or** `failed`,
  and the agent explains the outcome in the same reply.
- Rollback text describes a simulated archive; there is no restore button in the baseline.
- All devices are simulated and labelled so in the UI.
